# Air780EHV 桌面电话与短信控制台

将本项目打包成 Mac App 后，用户可以通过 USB 连接 Air780EHV，使用设备与 SIM
信息查看、短信收发、电脑实时通话、录音、AI 电话接听、钉钉短信推送、设备网络测试、
基站位置查询和 USB 4G 网卡共享。App 内含前端、Python 后端、配套固件、Lua 脚本和
刷写工具；收到 App 的用户无需安装 Python、Node.js、uv 或下载项目源码。

完整使用流程：**生成或获得 App → 准备兼容设备与 SIM → 首次全量刷写 → 确认设备在线
→ 配置所需服务 → 使用各项功能**。首次刷写和配置完成后，日常只需打开 App、插入设备。
AI 接听需要自己的 Realtime API 账户，钉钉推送需要自己的群机器人；这些服务不随 App 提供。

## 快速开始：生成和分发 Mac App

### 1. 准备构建环境和配套文件

构建需使用 Apple Silicon Mac（M1/M2/M3/M4 等，`uname -m` 为 `arm64`），安装
Node.js 22+、npm、uv、ripgrep（`rg`）及 macOS 的 `iconutil`。构建过程中会下载依赖，
首次构建需保持电脑联网。当前仅提供 macOS arm64 App，不提供 Intel Mac 或 Windows 安装包。

```sh
git clone https://github.com/jik92/Callweb_air780EHV.git
cd Callweb_air780EHV
```

**首次克隆后必须另行准备以下两个文件**，`tools/` 和 `firmware/` 不在 Git 仓库中，
构建脚本目前不会自动下载它们：

| 文件位置 | 获取方式和要求 |
| --- | --- |
| `tools/luatos-cli` | 从 [CLI v1.11.0 发布页](https://github.com/wendal/luatos-cli/releases/tag/v1.11.0) 下载 macOS ARM64 版本，解压后将可执行文件放到此路径 |
| `firmware/LuatOS-SoC_V2052_Air780EHV_13.soc` | 从 [合宙 Air780EHV 固件资料](https://docs.openluat.com/air780ehv/luatos/firmware/version/) 获取对应版本；若当前下载页未列出 V2052，向项目维护者索取该固定版本，不能直接用其他版本或其他型号替换 |

准备后确认路径与架构：

```sh
chmod +x tools/luatos-cli
file tools/luatos-cli
ls -lh firmware/LuatOS-SoC_V2052_Air780EHV_13.soc
```

`file` 输出应包含 `arm64`。无需为打包下载整个官方 SDK。

### 2. 一键生成 App

在项目根目录执行：

```sh
./scripts/build-mac.sh
```

脚本安装锁定依赖、检查和构建前端、生成图标、冻结 Python 后端，并创建 App 和 DMG。
构建输出：

- App：`build/mac/mac-arm64/Air780 Console.app`
- DMG：`build/mac/Air780-Console-0.1.2-arm64.dmg`（版本以 `desktop/package.json` 为准）
- 只生成 App 目录：`./scripts/build-mac.sh app`

App 内的 Lua 脚本是构建时快照，修改项目后需要重新打包，再使用新 App 更新设备脚本。
一键构建只生成安装包，**不会给连接的设备刷写、发送短信或拨打电话**。

### 3. 分发与安装

将 DMG 分发给用户，用户打开 DMG，把 `Air780 Console.app` 拖到「应用程序」目录后打开。
也可以分发完整的 `.app` 包，不能只复制其中的可执行文件。更新时先在右上角菜单选择
「退出」，替换 App 后再打开；仅关闭窗口不会退出后台。

当前生成的 App 未配置 Apple Developer ID 签名和公证，macOS 可能阻止首次打开。
面向普通用户正式分发前，发布者应配置签名与公证；当前一键命令不包含该发布步骤。

安装包不包含构建者的 SIM 信息、短信、录音、API Key 或钉钉凭据，用户需填写自己的配置。
App 使用本机 `127.0.0.1:9012`，无需启动开发控制台。

## 用户准备：设备、SIM 和电脑

| 需要准备 | 具体要求 |
| --- | --- |
| 电脑 | Apple Silicon Mac，运行本项目生成的 macOS arm64 App |
| 设备 | **Air780EHV** 开发板，具有可连接 Mac 的模块 USB 数据接口、SIM 卡槽、BOOT/下载和复位操作方式；不要仅购买需要自行焊接的裸模组 |
| 音频方案 | 当前 `lua/call_player.lua` 使用 **ES8311**，并固定对应 I²C、DAC 和 PA 控制配置。使用与项目音频配置一致的开发板；购买其他核心板或自制板时先确认接线、芯片和引脚，不能保证任意 Air780EHV 板均可直接通话 |
| 天线与供电 | 配套蜂窝天线、稳定供电；按开发板说明安装和接线 |
| USB 数据线 | 能传输数据的线，接模块 USB 数据接口；仅供电接口或仅充电线不能枚举应用口和下载口 |
| SIM 卡 | 已激活、可在当地注册网络的 SIM；使用全部功能需开通语音/VoLTE、短信收发和移动数据，购买前向运营商确认。仅支持数据的物联网卡不能满足电话和短信需求 |
| 麦克风与耳机 | 普通电脑实时通话需要 Mac 麦克风权限，建议使用耳机；AI 接听不使用电脑麦克风 |
| AI 服务与钉钉 | AI 接听准备对应提供方的 Realtime API Key、可用模型和额度；钉钉推送准备群自定义机器人的 Webhook 和 SEC 加签密钥 |

合宙的 [Air780EHV 通话音频说明](https://docs.openluat.com/air780ehv/luatos/app/volte/audio_play_to_call/)
列出了整机开发板、核心板与音频配件方案，并要求使用具备 VoLTE 功能的电话卡。
本项目的板级音频配置仍需与实际硬件匹配。电话号码、短信、流量和 AI API 费用由用户自行承担。

## 首次使用：在 App 内刷写并连接设备

1. 设备断电时按开发板说明装好 SIM 和天线，再通过 USB 数据线连接 Mac。
   打开 App，进入「硬件刷写」。新设备尚未安装本项目程序时，总览没有数据是正常现象。
2. 首次安装选择 **「底层固件＋脚本」**，点击「准备并校验文件」，确认型号为 Air780EHV。
   此步骤准备 App 内的 V2052 固件与配套脚本，不写入设备。有旧数据的设备先自行备份。
3. 关闭 **「设备串口连接」** 开关，等待「串口已释放 / 桥接：已暂停」。关闭其他串口工具。
4. 按住设备 BOOT/下载键，复位或重新上电后松开 BOOT；具体按键和接口以开发板说明为准。
   点击「选择下载串口」，在弹窗选择新枚举的下载口。
   本机常见下载口后缀为 `11`，应用口为 `17`，日志口为 `13`；端口以实际枚举为准，
   不要把应用口或日志口当下载口。只选择串口还不会开始刷写。
5. 勾选型号、分区、备份和 BOOT 状态确认项，点击「开始刷写」。保持供电和 USB 连接，
   等待「分区刷写与重启已确认」；刷写期间不关闭 App、不刷新页面、不按设备按钮。
6. 确认 BOOT 已松开，设备正常启动，**重新开启「设备串口连接」**；也可点击「恢复后台桥接」。
   刷写成功后仍需执行这一步，否则总览会保持离线。
7. 返回「设备总览」，等待设备在线、应用版本和 SIM 信息出现。
   当前源码应用版本为 `001.999.016`（以 `lua/main.lua` 为准），SIM 应就绪，网络应已注册。
   手机号未提供不代表 SIM 不可用；可在确认真实号码后手动设置，不能由 ICCID/IMSI 推算。

已安装匹配 V2052 固件的设备，后续更新业务程序可选择「仅更新脚本」。
超时或失败后先看刷写日志和 BOOT 状态，再手动处理；不会自动重复刷写。
完整协议、日志与浏览器步骤见 [Chrome 直接串口刷写](#chrome-直接串口刷写)。

## 各功能的使用和验证

| 功能入口 | 使用方法与成功判断 |
| --- | --- |
| 设备总览 | 查看在线状态、应用版本、SIM、网络注册和信号。先确认在线，再操作其他功能；点击「更新位置」获取大致基站位置，需要可用数据网络和定位服务 |
| 右上角 macOS 菜单栏 | 图标旁显示 `Air780 · CSQ/31`，点击查看设备、版本、SIM 状态、CSQ、RSRP 和完整串口号；每 2 秒更新，离线或暂停不显示旧信号。可打开控制台、数据目录、日志或退出 |
| 短信管理 → 短信收发 | 输入用户确认的号码与内容并手动发送；收件和发件支持搜索、筛选。提交短信中心成功不等于手机已收到；超时结果未知时先核实，避免重复发送 |
| 实时通话 → 通话控制 | 允许麦克风权限，输入号码手动拨号，或在来电弹窗点「接听 / 拒接」。用电脑麦克风和耳机通话，支持静音、按键音；结束后查看、回放或下载录音 |
| 实时通话 → AGENT设置 | 选择 AiHubMix 或 OpenAI，填写自己的对应 API Key、该账户支持的 Realtime 模型、声音、开场白和业务场景指令；启用并保存后点「验证已保存的连接」。验证通过后，来电时手动选择「Agent接听」 |
| 短信管理 → 钉钉推送 | 填写群机器人的 Webhook 与 SEC 加签密钥，保存后发送固定测试消息；确认群收到，再启用新短信推送。新短信会发送号码、时间和完整内容，历史同步及发件短信不推送 |
| 网络测试 | 手动发起设备端 HTTP/HTTPS 请求，用 SIM 的数据网络检测连通；显示响应状态、耗时与响应头，电脑联网不能替代设备联网检查 |
| 网络测试 → USB 网卡 | Mac 选择 ECM，再手动开启。等系统识别 USB 网卡并获取 DHCP 地址后，在 macOS 网络设置确认连接；电脑是否走 4G 取决于路由和服务顺序，App 不自动关闭 Wi-Fi |

AI 通话会把通话音频和场景指令发送给所选 API 提供方，需电脑能连接该服务且账户有可用额度。
模型是否可用以实际账户和「验证已保存的连接」结果为准。基站定位只提供大致位置，
会使用合宙与地址解析服务。普通电话、短信、数据业务依赖 SIM 套餐、覆盖与运营商配置。

设备不会上电自动拨号或自动接听，Agent 也需要手动接听来电。
来电通知和电脑/AI 通话需要 App 及接听页面持续运行；来电时打开控制台查看弹窗并手动接听。
Mac App 的关闭窗口操作只是隐藏，页面仍保留；退出 App 或在 Chrome 中真正关闭接听页面
会中断连接。菜单栏状态更新不代表支持无人值守自动接听。

首次验收建议依次确认：设备在线及 SIM 注册 → 给自己授权的测试号码收发一条短信
→ 普通电话双向听感与录音 → AI 连接验证和手动接听 → 钉钉测试与新短信推送
→ 设备网络请求和 ECM 联网。软件构建成功不能替代这些实机检查。

## 日常使用、更新和常见问题

日常打开 App，设备正常上电并连接 USB，等待总览在线即可；不必每次刷写。
「硬件刷写」的串口连接开关保持开启。窗口关闭后菜单栏及后端仍运行；需要结束程序时，
在菜单栏选择「退出」。升级 App 不会自动升级设备，需按需要执行脚本或全量更新。

| 现象 | 处理方法 |
| --- | --- |
| 只能看到串口号，看不到设备信息 | 进入「硬件刷写」，开启「设备串口连接」并点击「重新连接 / 释放开发占用」。App 会请求同项目开发桥接释放相同串口；正在通话、发短信或执行设备操作时需等待完成。其他串口工具或浏览器占用需自行关闭 |
| 刷写成功但总览仍离线 | 松开 BOOT、正常启动并开启串口连接；无需仅因为桥接暂停而再次刷写 |
| 没有下载串口或 BOOT 握手超时 | 检查设备型号、USB 数据接口、数据线和供电，重新进入 BOOT 模式并重新选择下载口 |
| SIM 未就绪或网络未注册 | 检查插卡、激活状态、卡槽、天线、套餐及当地覆盖；SIM 注册需要时间，不要把没返回手机号当作注册失败 |
| SIM 在线但无法通话 | 确认套餐支持语音/VoLTE，检查通话和音频就绪状态、ES8311 与板级接线配置；只有数据功能的卡不能代替电话卡 |
| AI 连接验证失败 | 检查所选提供方与 Key 是否对应、模型访问权限、额度和电脑网络；验证通过后再手动接听 |
| 钉钉测试失败 | 核对已保存的 Webhook、加签密钥、机器人安全配置和电脑网络，查看最近推送状态 |
| ECM 开启但电脑没有网络 | 检查 USB 网卡是否出现并取得 DHCP 地址、SIM 数据注册及系统路由；恢复串口可关闭网卡，必要时松开按键后拔插 USB 正常上电 |
| 9012 端口被占用 | 退出重复 App 或明确占用该端口的服务后再启动；App 不会结束其他项目进程 |
| macOS 阻止安装包启动 | 当前包未签名、公证；发布者需提供完成签名公证的安装包，不能把首次打开成功视为已完成发布配置 |

用户数据与日志位于 `~/Library/Application Support/Air780 Console/`，包含 `data/` 和 `logs/`，
可从菜单栏打开。短信、录音、Agent 配置和机器人凭据留在本机；备份时保留此目录，
反馈问题时只提供所需阶段和错误信息，不公开真实 SIM 标识、短信内容或密钥。
开发环境的数据在项目 `data/`，不会自动迁移到 App。

桌面实现和模拟串口冒烟说明见 [桌面应用文档](desktop/README.md)。

cd /path/to/Callweb_air780EHV

## 烧录

可在控制台使用 [Chrome 直接串口刷写](#chrome-直接串口刷写)，也可使用下面的 CLI 脚本。
使用 CLI 前先执行 `./scripts/dev-console.sh stop`，烧录完成后执行
`./scripts/dev-console.sh start`。浏览器刷写则在页面暂停和恢复桥接，无需停止后端。

首次使用 LuatOS 或更换底层固件：

```sh
./scripts/flash.sh
```

后续仅修改 Lua 脚本：

```sh
./scripts/flash-script.sh
```

macOS 上 CLI 的 USB 接口自动选择可能选错端口。如果自动进入下载模式超时，
按住“下载/BOOT”键，同时复位或重新插入 USB，再松开下载键。
下载模式通常出现 `/dev/cu.usbmodem0000000000011`（VID/PID `17D1:0001`）；
实际路径以串口列表为准，可将端口传给烧录脚本：

```sh
./scripts/flash.sh /dev/cu.usbmodem0000000000011
```

烧录期间保持 USB 连接，不按按钮。更换底层固件会替换设备当前应用。
已生成包含本项目脚本的 `build/air780ehv-sim-query.soc`，可用于 LuaTools 全量烧录。

## 读取手机号

烧录并启动后：

```sh
.venv/bin/python scripts/device.py status
```

输出 `mobile.number`，以及 SIM 就绪状态、ICCID、IMSI、注册状态和信号。
查询程序 `001.999.001` 还返回当前 SIM 卡槽、RSSI、RSRP、RSRQ、SNR，
以及 `mobile.scell()` 返回的服务小区（MCC/MNC、Band、CID、TAC、PCI、EARFCN）。
这些小区和信号数据反映当前连接的网络，不属于 SIM 卡的固定资料。
退出码：`0` 已返回号码；`2` 收到状态但号码为空；`1` 没有设备状态响应。
串口查询兼容参考项目的 `get_status` 协议。

本机实测 USB VUART 为 `/dev/cu.usbmodem0000000000017`，可直接指定：

```sh
.venv/bin/python scripts/device.py status --port /dev/cu.usbmodem0000000000017
```

2026-10-11 实机验证：V2052 固件和查询脚本烧录成功；返回本项目名称与版本，
SIM 就绪、网络状态为 1（已注册）、CSQ 为 31，ICCID 和 IMSI 可读取，手机号为空。
完整结果在 `logs/luatos-status.json`，成功烧录日志在 `logs/flash-retry.log`。
这里确认的是接口未返回号码，不能仅据此认定空值的具体原因。
扩展查询实测：SIM0；服务网络 MCC/MNC 为 460/11，Band 8；
RSRP -67 dBm，RSRQ -8 dB，SNR 15 dB。这些值会随时间和设备位置变化。

`mobile.number(0)` 只能读取 SIM 中预先存储的号码，必须等 SIM 准备就绪。
空值并不表示 SIM 不正常，不能由 ICCID、IMSI 推算出手机号。
若没有存储号码，需要通过运营商账户或其他已授权方式确认后配置。

本机实测 LuatOS 二进制日志口为 `/dev/cu.usbmodem0000000000013`：

```sh
tools/luatos-cli log view-binary --port /dev/cu.usbmodem0000000000013 --baud 921600 --probe
```

原始 AT 固件诊断命令（仅适用于运行 AT 固件时）：

```sh
.venv/bin/python scripts/device.py at --port /dev/cu.usbmodem0000000000013
```

日志保存在 `logs/`；设备 SIM 信息请留在本机。

## 发送短信

程序 `001.999.002` 在收到明确的 `send_sms` 命令后调用官方
`sms.sendLong(...).wait()`；上电不会自动发送。

```sh
.venv/bin/python scripts/send_sms.py \
  --port /dev/cu.usbmodem0000000000017 \
  --to <收件号码> --content '<短信内容>'
```

1. 打开 Mac App；开发环境则执行 `./scripts/dev-console.sh start`。先备份设备文件与录音，

| 暂停被拒绝 | 结束通话，等待短信发送和当前设备操作完成；不要同时操作其他控制台页面 |
| Chrome 没有列出下载口 | 检查数据线与供电，重新进入 BOOT 下载模式后再打开选择弹窗 |
| 串口无法打开或被占用 | 关闭其他串口工具及正在使用该端口的浏览器页面，确认桥接已暂停 |
| 握手超时 | 重新进入 BOOT 模式，重新选择枚举后的下载口，手动重试 |
| 传输、校验或重启报错 | 保留包含阶段、命令与字节数的完整刷写日志；结果可能未知，不会自动重试。重新进入 BOOT 模式后手动处理 |
| 刷写成功但总览离线，并提示桥接暂停 | 前往「硬件刷写」点击「恢复后台桥接」；这不表示刷写失败，无需因此再次刷写 |
| 恢复桥接后仍离线 | 松开 BOOT 后正常复位或重新上电，确认应用口已重新枚举，再检查总览状态；不要把下载口设为应用串口 |
| 刷新或关闭页面后桥接仍暂停 | 重新打开「硬件刷写」菜单，可读取暂停状态并手动恢复；本机后端保持运行时，页面关闭不会自动恢复桥接 |

「停止刷写」会中断当前任务，可能已写入部分分区，不能当作撤销。
停止、超时或断线后，页面保持结果未知或失败，桥接继续暂停；请按日志定位，
不要自动重试或连续重复点击刷写。日志不代表应用已经启动，最终以总览在线和设备版本回应为准。

2026-10-11 验证记录：自动检查通过，后端 61 项测试和前端模拟串口测试覆盖分片响应、
握手时序、可选 ROM 状态字节、数据块确认序号、CRC、断线及取消。用户在 Chrome
实际操作后报告刷写成功；恢复桥接后，本机 API 确认应用串口在线、设备就绪并返回
应用版本 `001.999.016`。这确认本次应用恢复正常，不等于两种刷写模式均完成独立实机验证。
