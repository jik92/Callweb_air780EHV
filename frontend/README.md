# Air780 设备后台

React + TypeScript + Vite + TanStack Query / Router + Ant Design + Tailwind CSS 4。
采用 Ant Design Layout / Sider / Header / Content / Footer 标准框架，带可折叠菜单和面包屑。
左侧一级菜单为设备总览、硬件刷写、网络测试、实时通话、短信管理。
实时通话包含通话控制与 AGENT设置，短信管理包含短信收发与钉钉推送；
收件箱/发件记录筛选在短信收发页面内。每次显示所选菜单内容，窄屏自动收起导航。
设备总览并列展示设备与 SIM 信息，短信收发并列展示记录与表单；窄屏上下排列。
不含登录和用户管理；窄屏自动改为上下排列。

```sh
npm ci
npm run dev
npm run build
```

开发地址：`http://127.0.0.1:9011`，需要先启动 9010 端口的 FastAPI 服务。
HTTP 获取初始快照；之后用 WebSocket 双向通讯，TanStack Query 维护服务状态缓存。

切换菜单保留短信草稿、搜索和筛选，通话组件持续运行，不因导航挂断。

设备总览的“设置本机号码”可填写在接收手机上确认的设备短信发件号码。
号码按 ICCID 保存在本机，显示来源“人工确认”，支持修改或移除；换卡不会沿用其他卡的标注。
SIM 自己返回号码时优先显示 SIM 值。收到短信的发送者号码不会被用于推断本机号码。
当前短信数据只有发件人号码，没有本机收件号码，因此不提供收件号码备选。
本机号码需在接收手机上确认后手动填写，不能使用设备收件箱中的发件人号码代替。
浏览器 WS 断线自动重连，20 秒心跳；短信 Mutation 不自动重试。
已发送短信会显示模块执行状态，未知结果不会误标为成功。

样式统一使用 Tailwind utility class，禁止手写原生 CSS 和内联 `style`。
`src/tailwind.css` 只保留 Tailwind 导入指令；Ant Design 使用主题 token 和自带样式。
`npm run check` 自动检查样式约束及格式；完整开发约定见 [AGENTS.md](../AGENTS.md)。

## WebSocket 实时通话验证

拨号等待期间播放本地 450Hz 间歇提示音，接通、失败、挂断或断线时停止。
此提示音不表示运营商已确认对方响铃，也不发送给手机端。
页面下方提供持久化通话记录，包括号码、时间、结果和接通时长；结束后可回放/下载
双声道 WAV 录音。进行实时通话时回放暂停，避免录音进入麦克风。
录音从本功能部署后的新通话开始保存；未接通的拨号保留结果并显示无录音。

“实时通话”面板使用电脑麦克风和耳机，通过 `/ws/call` 发送和播放单声道
16 位 PCM，按通话协商结果使用 8/16kHz；浏览器麦克风由 AudioWorklet 重采样并分为 40ms 帧。
先允许浏览器使用麦克风，再输入接听号码点击拨号。支持挂断和麦克风静音。
拨号键盘支持点击数字、编辑光标位置、删除一位、清空、国际区号 `+` 和填入上次号码。
接通后，发起通话的页面可发送 `0–9`、`*`、`#`；聚焦键盘也可使用实体键盘。
按键音使用带内 DTMF：两组标准频率合成 160ms 双音，数字间留 80ms 空隙，
经现有 PCM 通道送入设备。发送时暂时替换麦克风音频，静音不影响按键。
这是音频按键，不是运营商带外 DTMF 信令；语音菜单识别率需实机验证。
不支持拨号前发送 `*`/`#` USSD 指令。号码与通话按键不写入浏览器长期存储。
实时通话无固定 90 秒强制结束限制，仅一页拥有通话音频；断开页面不会重拨，后台请求挂断，
设备音频输入超时也会挂断。需要设备应用 `001.999.008` 或更新版本。

此版本用于验证链路，音质、延迟和回声处理需实机评估。页面为 localhost 安全上下文；
远程部署需要 HTTPS、访问控制及相应的后端 Origin 配置。

实时通话下增加「AGENT设置」子菜单，配置提供方、Key、模型、声音、开场白和 AGENT.md。
切换菜单保留场景编辑草稿；保存或验证不拨号、不接听。来电弹窗中「Agent接听」使用后台音频，
普通「接听」保留电脑麦克风通话；Agent通话不启用电脑静音或按键音控件。

控制台名称统一由 `src/constants.ts` 的 `APP_NAME` 配置，当前为“智能语音客服”。
侧栏、页头、页脚和 HTML 页面标题使用同一常量。总览保留连接状态和 SIM 信息，
不再展示“当前设备”标题和硬件型号名称。

## Chrome 硬件刷写

完整使用步骤和故障处理见 [主文档：Chrome 直接串口刷写](../README.md#chrome-直接串口刷写)。
使用桌面 Chrome，通过 `http://127.0.0.1:9011` 打开「硬件刷写」菜单。
固定支持本项目 V2052 Air780EHV_13 固件，可选择「仅更新脚本」或「底层固件＋脚本」。

顺序为：准备并校验文件 → 暂停后台桥接 → 手动进入 BOOT 模式 → 选择下载串口
→ 确认并开始刷写 → 正常上电 → **恢复后台桥接** → 总览确认在线及应用版本。
刷写成功不会自动恢复桥接；总览会显示暂停提示和「前往恢复」入口。
切换菜单保留刷写任务和日志，刷新或关闭页面会丢失页面内任务状态，后台仍保持暂停。
停止、超时、断线不自动重试，可能需要重新进入 BOOT 模式。

文件准备经本机 API 完成，串口传输由 `src/webFlash.ts` 使用 Web Serial 执行。
HTTP 通信集中在 `src/connection.ts`；只点击串口授权按钮时请求 Chrome 权限，
只有点击「开始刷写」后才打开串口并写入。浏览器需安全上下文，不支持时页面给出提示。
`npm run check` 包含模拟串口测试，不打开真实串口；构建通过不代表实机烧录通过。

「短信管理 → 钉钉推送」包含 Stream 应用机器人配置，支持引用新推送短信并 @ 回复。
配置应用凭据并开启连接与 SMS 回复；群 ID 和用户 ID 可留空以允许全部，也可填写限制范围。
仅连接时可发现来源 ID。展示连接状态与结果记录，
密钥不回显；引用缺失时要求显式短信编号。未做真实发送测试，使用步骤见根 README。
