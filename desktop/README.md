# Apple Silicon macOS 应用

Electron 封装现有控制台，支持 M4 与其他 Apple Silicon Mac。应用包含前端、Python
后端、ARM64 LuatOS CLI、固定 V2052 Air780EHV_13 固件与构建时的 Lua 项目。
运行应用不需要另装 Node、Python 或 uv。

## 一键编译

在 Apple Silicon macOS 的项目根目录执行：

```sh
./scripts/build-mac.sh
```

构建机器需要 Node.js 22+、npm、uv，以及已有 `tools/luatos-cli` 和固定固件。
首次构建需要联网下载锁定依赖；脚本安装依赖、检查并构建前端、生成图标、冻结 Python
后端，最后创建 arm64 `.app` 与 DMG。

- 应用：`build/mac/mac-arm64/Air780 Console.app`
- 安装镜像：`build/mac/Air780-Console-0.1.3-arm64.dmg`
- 只生成应用目录：`./scripts/build-mac.sh app`

将 DMG 中的应用拖到「应用程序」目录后打开。当前产物用于本机测试，未配置 Apple
Developer ID 签名和公证；正式分发前需要对应证书与公证配置。

## 菜单栏图标

右上角 macOS 菜单栏显示设备图标与当前 CSQ 信号（0–31，数值越大信号越强）。
展开菜单可查看连接状态、设备名称、应用版本、SIM 就绪状态、CSQ、RSRP 和完整串口路径。
每 2 秒读取一次本机状态，窗口隐藏后仍更新；离线、桥接暂停或 SIM 未就绪时不会显示旧信号。
可选择：打开控制台、在 Chrome 中打开、
查看数据目录、查看日志、退出。关闭主窗口只隐藏窗口，后端仍运行；退出会停止
本应用启动的后端并释放串口。启动第二个实例会显示已有窗口。

应用后端只监听 `127.0.0.1:9012`；不会接管开发环境 9010/9011。
9012 被其他服务占用时会报错，不结束其他进程。同一应用串口只能由一个进程读取。

在「硬件刷写」使用「设备串口连接」开关：关闭会暂停当前桥接并释放串口；
开启会连接设备。若开发控制台占用了同一串口，应用会请求其暂停桥接，
保留开发服务和数据。正在通话、发送短信或执行设备操作时不会接管，需等待完成。
开关已开启但提示占用时，点击「重新连接 / 释放开发占用」。其他串口工具需自行关闭。

数据与日志保存在 `~/Library/Application Support/Air780 Console/` 下的 `data/` 和 `logs/`，
不会从项目目录复制短信、录音或 API Key；首次运行需要重新填写本机设置。
应用更新不会删除该目录，项目开发数据仍保留在原 `data/` 中。

硬件刷写可直接使用应用里的串口选择对话框，也可从菜单在 Chrome 中打开控制台。
两种入口共用应用后端，仍需手动暂停/恢复桥接。只授权用户所选下载口，不自动刷写。
安装包内的 Lua 项目是构建时的快照；修改源码后重新编译应用。
普通通话首次使用麦克风会请求 macOS 权限；Agent接听无需电脑麦克风。

## 验证

```sh
npm run check --prefix desktop
"build/mac/mac-arm64/Air780 Console.app/Contents/MacOS/Air780 Console" --smoke-test
```

冒烟模式使用独立临时测试数据和不存在的模拟串口，不打开真实设备，不发短信、不拨号、
不烧录。检查封装后端、页面、Web Serial、安全上下文、菜单栏图标，随后退出并释放 9012。
真实通话、录音和应用内刷写需另行实机验证。
若已运行正式应用，可在冒烟命令前加 `AIR780_SMOKE_PORT=9015`，使用独立 9xxx 端口验证。

新版包含钉钉 Stream 收件推送与引用回复：在「短信管理 → 钉钉推送」单独配置应用机器人；推送目标群留空使用允许回复的群 ID，回复范围的群 ID 和用户 ID 可留空以允许全部，
也可填写 ID 限制范围，开启短信回复，保持 App 与设备在线，即可引用新推送短信并 @ 机器人回复。无需公网端口。
仅用应用机器人即可推送和接收 @，两个功能分别启用；原自定义 Webhook 推送也是独立可选模式。完整设置与使用流程见根 README。
